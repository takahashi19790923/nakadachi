## 2. 決済まわり（直した）

- 支払い成立の UPDATE が無条件で、返金の直後に届くと refunded を succeeded で上書きして公開する → 状態を WHERE に入れる（返金側と同じ形）
- 申し立ても返金済みの上に disputed を書かない
- Webhook が `received` のまま止まったものはどの警報にも掛からなかった → 15分超を数え、失敗した Webhook についても**1日1通メール**（以前は投稿単位の異常しかメールしていなかった）
- ログアウトだけ CSRF トークンを照合していなかった

## 3. 運用（直した）

- **統合テストは落ちても終了コードが 0 だった。** PGlite の `close()` が WASM の終了処理で exit code を上書きする。**CI の「統合テスト」は落ちるはずの変更でも緑だった。** teardown で控えて戻す。わざと1件落として 1 になることを確認した
- 管理操作を1件でも行った利用者は退会削除が毎日失敗し続けた（`admin_actions.admin_id` が RESTRICT）→ SET NULL。「誰が」は audit_logs に残る
- 退会削除の連鎖削除に索引の無い外部キーが4つ → 索引を足した（マイグレーション 0003）
- 発信者情報の掃除が上限なしの `DELETE … RETURNING` で全行を運んでいた → 5000件ずつ・rowCount
- `/api/health` に上限が無く、DB が詰まると「返ってこない」になっていた → 5秒で 503
- 本番で `RESEND_API_KEY` が無いと黙って送信を飛ばしていた → fail-close
- OPERATIONS の PITR「24時間」は誤り。**Free は 6時間**（API で実測）

## 4. 速度（直した）

DB がシンガポール（片道 100〜250ms）なので、速さは往復の回数で決まる。

| どこ | 前 | 後 |
|---|---|---|
| 一覧（トップ・カテゴリ・地域・検索・マイページ） | 行を取ったあと写真をもう1回引く | 相関サブクエリで同じ文に（毎回1往復減） |
| 詳細（6ルートが使う） | 本文→写真を直列 | 同時に投げる |
| 決済待ち画面（5秒ごとに読み直す） | 所有者確認→決済状況を直列 | 同時に投げる |
| 写真の配信 `/media` | セッション→行を直列 | 公開中なら閲覧者を待たずに返す（ログイン中の詳細ページで写真5枚＝5往復減） |
| フォーム送信 | **セッションを2回引いていた**（RR が再読み込みで新しい Request を作るため） | AppContext をキーに（約20の送信経路すべて） |
| HTML | **Cache-Control が1つも無かった**（共有キャッシュに別人のマイページが載る余地） | 一律 `private, no-store` |
| `/assets/*` | 既定の `max-age=0, must-revalidate`（186KB の JS を遷移のたびに再検証） | `public/_headers` で1年 immutable |
| 通報の3画面 | zod 本体＋日本語ロケール **70KB** を落としていた | 依存の無い定数ファイルへ（**461バイト**に） |
| 一覧の先頭3枚 | lazy | eager / fetchpriority=high（LCP）、カードは prefetch="intent" |

## 5. ★経路障害と Hyperdrive★（今夜いちばん大きい変更）

**22:50 JST 頃から、Cloudflare（NRT）→ Neon（ap-southeast-1）の問い合わせが 2〜40秒に振れる
時間帯が2時間以上続き、00:20 頃には `/api/health` が 100% タイムアウト（DB を使う画面が全部落ちる）
まで悪化した。** 切り分け:

- 同じ DB へ手元の PC からは 70ms、Vercel（fuyou）からは 250ms → Neon 本体ではない
- HTTP（`poolQueryViaFetch`）でも WebSocket でも同じ（preview で両方試した）
- 「1回の問い合わせに 4秒の上限を付けて張り直す」も preview で試したが、張り直しも同じだけ詰まって 500 が増えた
- Neon・Cloudflare のステータスページは両方とも正常のまま

**Hyperdrive 経由に切り替えた直後から、本番の一覧が 0.22〜0.70秒（15回連続）、`/api/health` が
120〜150ms（10回連続）に戻った。** 平常時（162〜331ms）よりも速い。Hyperdrive は DB の近くの
Cloudflare 拠点で接続を張りっぱなしにして使い回すので、リクエストごとに新しい接続を張らない。

- **キャッシュは切ってある**（`--caching-disabled=true`）。切らないと投稿した直後の一覧に最大60秒古い結果が出る
- ローカル・テストは従来どおり直接（binding が無い環境は自動で退避路）
- アイドル明けの cold start は 742ms（直接のとき 653ms）で変わらない
- 手順・切り戻しは `DEPLOYMENT.md`「Hyperdrive」。切り戻しは `wrangler.jsonc` の `hyperdrive` を消してデプロイ、または `wrangler rollback`

書き込みの経路は、同じ `pg` + drizzle の組み合わせで統合テスト175件（トランザクション含む）が通っている。
Hyperdrive を通した実書き込みは preview で確かめた: 詳細ページを3回開いて `view_count` が 1 → 4
（応答後の UPDATE が Hyperdrive 経由で届いている）。本番も同じコードと自分用の Hyperdrive 設定。
★本番の定期処理（毎時の UPDATE）は `wrangler tail` が数分で切れて捕まえられなかった。★
次の :20 JST（19:20 UTC）の日次と合わせて、朝に Cloudflare のダッシュボード（Workers → nakadachi-production → Logs / Cron）で
「cron finished」が出ているか一度見てほしい。
